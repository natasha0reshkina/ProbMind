# ProbMind

ProbMind — учебный веб-сервис по теории вероятностей. Он хранит историю ответов студента, оценивает освоение тем и устойчивость типичных ошибок, подбирает следующие диагностические и практические задания и формирует план повторения.

В проекте пять тем: условная вероятность, независимость событий, p-value и проверка гипотез, закон больших чисел и интерпретация случайности.

## Что реализовано

### Студент

После входа студент видит текущий уровень освоения тем, активные типичные ошибки и рекомендации по дальнейшей работе.

Доступны:

- адаптивная диагностика из 15 вопросов;
- сохранение и продолжение незавершённой диагностики;
- обратная связь после каждого ответа;
- итоговый отчёт по диагностике с точностью, результатами по темам и выявленными типичными ошибками;
- история диагностик и сравнение двух завершённых сессий;
- отдельная страница каждой выявленной ошибки с историей наблюдений и объяснением, на чём основан вывод;
- адаптивная практика по выбранной теме или конкретной ошибке;
- сохранение и продолжение незавершённой практики;
- задания на коррекцию и перенос знания в другую формулировку;
- план повторения с приоритетами, возможностью отметить шаг выполненным или пропустить его;
- статистика изменения освоения тем между завершёнными диагностиками;
- рекомендации по следующим шагам;
- уведомления о готовности диагностики, изменении плана и изменении состояния типичных ошибок;
- регистрация, вход, выход и изменение отображаемого имени в профиле.

Новая регистрация создаёт аккаунт с ролью студента.

### Преподаватель

Преподаватель работает с результатами группы и банком заданий.

Доступны:

- сводка по группе: число студентов, диагностик, ответов, средняя точность и среднее освоение тем;
- список студентов с поиском и сортировкой;
- профиль отдельного студента с освоением тем, активными ошибками, неверными ответами и изменениями плана повторения;
- статистика повторной работы и эффективности коррекционных заданий;
- аналитика заданий: число ответов, доля правильных ответов, сложность, различающая способность, распределение вариантов и время ответа;
- банк заданий с фильтрацией по теме и состоянию;
- создание новых заданий;
- версионирование заданий: изменение формулировки создаёт новую версию, а старые ответы остаются связаны с предыдущей версией;
- публикация и архивирование заданий;
- настройка вариантов ответа и связей дистракторов с типичными ошибками;
- выгрузка результатов студента, распространённости ошибок по группе и статистики заданий в `.xlsx`;
- исследовательская аналитика совместной встречаемости ошибок, калибровки диагностической уверенности и группировки студентов по профилю результатов;
- отдельные API и страницы для когортных сравнений и психометрических показателей заданий.

### Администратор

Администратор имеет доступ к административным разделам и к преподавательской аналитике.

Доступны:

- просмотр всех аккаунтов;
- смена роли пользователя;
- активация и деактивация аккаунтов;
- журнал административных изменений с состоянием данных до и после операции;
- мониторинг состояния приложения;
- число запросов и ошибок API;
- среднее и максимальное время ответа по маршрутам;
- список наиболее используемых и наиболее медленных маршрутов;
- информация о процессе API: время работы, память, число процессоров и потоков;
- доступ к результатам студентов, банку заданий, исследовательской аналитике и экспортам.

## Банк заданий

При первом запуске база заполняется опубликованным банком из 85 заданий:

- 45 диагностических;
- 20 коррекционных;
- 20 заданий на перенос.

На каждую из пяти тем приходится по 17 заданий. В банке есть базовый, средний и продвинутый уровни сложности. Продвинутые задания включают, например, расчёты по формуле Байеса с редкими событиями, вопросы о попарной и совместной независимости, множественные проверки гипотез, выборочную ошибку и сходимость, а также задачи о неравномерных случайных распределениях.

Каждый неправильный вариант диагностического задания может быть связан с конкретной типичной ошибкой. Эта связь используется при обновлении состояния студента и выборе следующих заданий.

## Как работает адаптация

Выбор следующего диагностического вопроса выполняется на сервере. Приоритет кандидата зависит от:

- текущего освоения темы;
- уверенности в связанных типичных ошибках;
- времени с последнего показа задания;
- соответствия сложности текущему уровню;
- числа предыдущих показов;
- новизны задания;
- необходимости проверить перенос знания.

Повторные показы получают штраф, поэтому система старается не возвращать одни и те же вопросы без необходимости. В рамках незавершённой диагностической сессии выбор следующего вопроса стабилен: переход в историю и возврат к диагностике не создаёт новую точку прогресса.

Освоение темы пересчитывается по истории ответов с учётом сложности задания, давности наблюдения, диагностической значимости и заданий на перенос. Для типичных ошибок отдельно хранится набор подтверждающих и опровергающих наблюдений. На их основе рассчитываются уверенность, состояние ошибки и объяснение результата.

План повторения строится из слабых тем и активных ошибок. Приоритет шага зависит от уровня освоения, выраженности ошибки и времени с предыдущей практики.

## Архитектура

Проект разделён на frontend, backend API, фоновый worker и инфраструктурные сервисы.

```text
Browser
  |
  v
Nginx / React frontend
  |
  | /api
  v
ASP.NET Core API
  |
  +--> Application services
  |      |
  |      +--> Domain algorithms
  |      |
  |      +--> Infrastructure
  |              |
  |              +--> PostgreSQL
  |              +--> Redis
  |
  +--> Redis background queue --> .NET Worker
```

### Frontend

`frontend/` — React + TypeScript приложение на Vite.

Основные части:

- `src/pages` — страницы студента, преподавателя и администратора;
- `src/components` — таблицы, графики, индикаторы прогресса и общие элементы интерфейса;
- `src/auth` — состояние авторизации и защита маршрутов по ролям;
- `src/api` — Axios-клиент, access/refresh token и автоматическое обновление access token;
- `src/types` — типы данных API.

Для серверного состояния используется TanStack Query. Графики построены на Recharts. В Docker frontend собирается в статические файлы и раздаётся через Nginx; запросы `/api` проксируются в backend.

### Backend

Backend находится в `backend/ProbMind.sln` и состоит из нескольких проектов.

`ProbMind.Domain` содержит сущности и алгоритмы, которые не зависят от ASP.NET Core или базы данных. Здесь находятся расчёт освоения, оценка уверенности в типичных ошибках, адаптивный выбор вопросов, построение плана повторения, коррекционная логика, объяснение диагностических выводов, психометрика и агрегированная аналитика.

`ProbMind.Application` содержит прикладные сценарии: авторизацию, диагностику, практику, модель студента, рекомендации, план повторения, статистику, работу преподавателя, управление контентом, экспорт, уведомления и административные операции. Доступ к базе, кэшу, очереди и времени задаётся через интерфейсы.

`ProbMind.Infrastructure` реализует эти интерфейсы. Здесь находятся Entity Framework Core и PostgreSQL, репозитории и Unit of Work, Redis-кэш, Redis-очередь фоновых задач, PBKDF2-хеширование паролей, JWT и начальное заполнение базы.

`ProbMind.Api` содержит HTTP-контроллеры, ролевую авторизацию, Swagger, обработку ошибок, заголовки безопасности, request id, метрики запросов и поддержку idempotency key для изменяющих запросов.

`ProbMind.Worker` читает фоновые задания из Redis и пересчитывает пользовательскую и групповую аналитику вне HTTP-запроса.

`ProbMind.UnitTests` и `ProbMind.IntegrationTests` содержат модульные и интеграционные тесты.

### Хранение данных

Основное состояние хранится в PostgreSQL. В модели есть пользователи, темы, задания и версии заданий, варианты ответов, типичные ошибки и связи с заданиями, диагностические сессии и ответы, практические сессии, история освоения тем, диагностические наблюдения, планы повторения, рекомендации, уведомления, refresh token и журнал административных изменений.

Схема создаётся Entity Framework Core при запуске через `EnsureCreated`. Seeder добавляет темы, типичные ошибки, тестовые аккаунты и банк заданий. Если база уже существует, новые задания из расширенного банка добавляются без удаления существующих данных.

Redis используется для кэширования групповой статистики, idempotency-ответов и очереди фоновых задач.

## Авторизация и роли

Backend использует JWT access token и refresh token. Ролевые ограничения проверяются и на frontend-маршрутах, и на API-контроллерах.

Основные права:

| Раздел | Студент | Преподаватель | Администратор |
| --- | :---: | :---: | :---: |
| Диагностика и практика | да | нет | нет |
| Личная статистика и план повторения | да | нет | нет |
| Результаты группы и студентов | нет | да | да |
| Банк заданий | нет | да | да |
| Экспорт данных | нет | да | да |
| Управление пользователями | нет | нет | да |
| Журнал изменений | нет | нет | да |
| Метрики приложения | нет | нет | да |

## Локальный запуск

Основной сценарий запуска рассчитан на Docker Desktop и macOS.

1. Установить и открыть Docker Desktop.
2. В терминале перейти в папку проекта.
3. Запустить:

```bash
./Start_ProbMind.command
```

Скрипт при необходимости создаст `.env` из `.env.example`, соберёт API, worker и frontend, запустит PostgreSQL и Redis и дождётся готовности приложения.

После запуска:

- приложение: `http://127.0.0.1:8080`;
- Swagger: `http://127.0.0.1:8010/api/swagger`;
- health check: `http://127.0.0.1:8010/api/health`;
- readiness check: `http://127.0.0.1:8010/api/ready`.

Если macOS не разрешает запуск `.command`-файлов:

```bash
xattr -dr com.apple.quarantine .
chmod +x *.command
```

Остановка:

```bash
./Stop_ProbMind.command
```

Проверка сборки и тестов:

```bash
./Check_ProbMind.command
```

Для запуска без `.command`-скриптов можно использовать Docker Compose напрямую:

```bash
cp .env.example .env
docker compose up --build -d postgres redis api worker frontend
```

## Вход под разными ролями

После запуска открыть `http://127.0.0.1:8080/login` и использовать нужный тестовый аккаунт. Роль определяется аккаунтом, отдельного переключателя роли в интерфейсе нет.

| Роль | Логин | Пароль |
| --- | --- | --- |
| Студент | `student@probmind.local` | `Student123!` |
| Преподаватель | `teacher@probmind.local` | `Teacher123!` |
| Администратор | `admin@probmind.local` | `Admin123!` |

Дополнительно создаются 18 студенческих аккаунтов:

- `student01@demo.probmind.local` … `student18@demo.probmind.local`;
- пароль для всех: `DemoStudent123!`.

Аккаунт `student@probmind.local` получает начальные демонстрационные данные по освоению тем и нескольким типичным ошибкам, поэтому на нём можно сразу посмотреть часть студенческой статистики. Остальные студенческие аккаунты подходят для отдельных тестовых прохождений.

## Конфигурация

Локальные значения находятся в `.env.example`:

- имя базы PostgreSQL;
- пользователь и пароль PostgreSQL;
- ключ подписи JWT;
- порт API;
- порт frontend.

`Start_ProbMind.command` копирует этот файл в `.env`, если `.env` ещё нет. `.env` исключён из Git.

Значения из `.env.example` предназначены только для локального запуска. Для развёртывания вне локальной среды пароль базы и `JWT_SIGNING_KEY` нужно заменить.

## Тесты и CI

GitHub Actions запускается на `push` и `pull_request`.

Backend job:

1. поднимает PostgreSQL и Redis;
2. восстанавливает зависимости .NET;
3. собирает `ProbMind.sln` в Release;
4. запускает unit- и integration-тесты.

Frontend job устанавливает зависимости и выполняет production build.
