# ProbMind

## Как зайти как студент и весь функционал

Для локального запуска нужен Docker Desktop. Из корня проекта на macOS выполните:

```bash
xattr -dr com.apple.quarantine .
chmod +x *.command
./Start_ProbMind.command
```

После запуска приложение доступно по адресу `http://127.0.0.1:8080`.

Основной тестовый аккаунт студента:

- логин: `student@probmind.local`
- пароль: `Student123!`

Дополнительные демонстрационные аккаунты: `student01@demo.probmind.local` — `student18@demo.probmind.local`, пароль для всех — `DemoStudent123!`.

Студенту доступны:

- личный кабинет с профилем, текущим освоением тем, учебной активностью, рекомендациями, стриком и рейтингом;
- изменение отображаемого имени;
- добровольное участие в рейтинге;
- рейтинг по общему результату, освоению тем, диагностике, практике и стрику;
- адаптивная диагностика по пяти темам: условная вероятность, независимость событий, p-value и проверка гипотез, закон больших чисел, интерпретация случайности;
- диагностики, составленные преподавателем и назначенные всем студентам, конкретной группе или конкретному студенту;
- продолжение незавершённой диагностики;
- необязательный выбор степени уверенности: «совсем не уверен», «скорее не уверен», «скорее уверен», «полностью уверен»;
- возможность не указывать степень уверенности;
- необязательный ход рассуждения и отдельный комментарий преподавателю при ответе;
- обратная связь по обычным диагностическим заданиям;
- итоговый отчёт по диагностике с результатами по темам и выявленными типичными ошибками;
- история диагностик и сравнение двух завершённых диагностик;
- отдельный раздел типичных ошибок с объяснением состояния каждой ошибки;
- адаптивная практика по теме или выявленной ошибке;
- продолжение незавершённой практики;
- коррекционные задания и задания на перенос знания;
- интервальное повторение с индивидуальной датой следующего повторения и пересчётом интервала после оценки сложности повторения;
- вкладка «Уверенность в ответах» с фильтрацией по одной или нескольким степеням уверенности и группировкой ответов по темам;
- индивидуальный план повторения с приоритетами и отметками «выполнено» и «пропустить»;
- статистика изменения освоения тем по завершённым диагностикам и практике;
- персональные рекомендации и уведомления;
- раздел «Материалы и задачи» для личных материалов, заметок и отправки материалов преподавателю;
- общие задания преподавателя и личные заметки к ним;
- ответы преподавателя и пометка «разберём на паре»;
- вкладка «Индивидуальное задание» с назначениями, предназначенными только текущему студенту;
- экзамены с фиксированным набором вопросов, ограничением времени и скрытой обратной связью до завершения попытки;
- образовательные достижения, которые рассчитываются отдельно для каждого студента по его диагностике, практике, освоению тем, исправленным ошибкам, переносу знания и дням активности;
- сохранение уже полученного достижения за конкретным студентом;
- учебные циклы «диагностика до → материал → диагностика после» с индивидуальным прогрессом и изменением результата;
- регистрация нового аккаунта с ролью студента;
- выход из аккаунта с очисткой пользовательского клиентского кэша.

## Как зайти как преподаватель и весь функционал

После запуска приложения откройте `http://127.0.0.1:8080` и используйте:

- логин: `teacher@probmind.local`
- пароль: `Teacher123!`

Преподавателю доступны:

- сводка по группе с учебными показателями и темами, в которых чаще возникают ошибки;
- список студентов с поиском, сортировкой и переходом в индивидуальный профиль;
- профиль студента с освоением тем, изменениями плана повторения, активными типичными ошибками, неверными ответами и комментариями к решениям;
- скачивание индивидуального отчёта по студенту;
- создание учебных групп из выбранных студентов;
- назначение диагностик всем студентам, конкретной группе или конкретному студенту;
- конструктор диагностик из одной или нескольких задач;
- изменение аудитории уже созданной диагностики;
- публикация и скрытие преподавательских диагностик;
- добавление новой задачи вручную с темой, сложностью, условием, вариантами ответа, правильным вариантом и разбором;
- добавление выбранных задач в существующую диагностику;
- фильтрация банка конструктора по теме, сложности, источнику, времени и тексту задания;
- массовый импорт диагностических задач из CSV через шаблон, доступный в интерфейсе;
- банк диагностических, коррекционных и переносных заданий;
- создание новых версий заданий без потери связи старых ответов с предыдущей формулировкой;
- публикация и архивирование заданий;
- настройка вариантов ответа и связей неправильных вариантов с типичными ошибками;
- статистика заданий с долей ошибок по темам, временем ответа и таблицей метрик по отдельным задачам;
- просмотр уверенности студентов, включая уверенные ошибки и правильные ответы при низкой уверенности;
- просмотр комментариев к решениям в профиле студента; ход рассуждения сохраняется вместе с ответом и показывается преподавателю при разборе экзамена;
- вкладка «Индивидуальное задание» с подсказками о студентах, которым может потребоваться дополнительная работа, и ручным назначением практики, повторения, материала или разбора на паре;
- раздел «Материалы и задачи» с материалами от студентов, ответами преподавателя и пометкой «разберём на паре»;
- публикация общего текстового задания для студентов;
- создание экзамена на основе готовой диагностики;
- назначение экзамена всем студентам, конкретной группе или конкретному студенту;
- настройка ограничения времени экзамена;
- контроль числа завершивших экзамен студентов;
- просмотр ответов после завершения экзамена всей назначенной аудиторией: ответ студента, правильный ответ, результат, степень уверенности, время ответа, ход рассуждения и комментарий;
- создание учебных циклов «до и после материала» для всех студентов или выбранной группы;
- просмотр числа студентов, завершивших каждый этап цикла, и среднего изменения результата;
- просмотр рейтинга и стриков студентов;
- отключение публичного рейтинга для студентов с сохранением преподавательского просмотра;
- фильтрация рейтинга по категориям;
- выгрузка результатов студента, статистики заданий и агрегированных данных по группе в Excel `.xlsx`;
- дополнительные показатели качества заданий, когортная статистика и психометрические метрики через доступные преподавателю аналитические API и страницы;
- уведомления и профиль аккаунта.

## Полное описание архитектуры

ProbMind состоит из React-приложения, ASP.NET Core API, фонового .NET Worker, PostgreSQL и Redis. Локальный запуск объединён через Docker Compose. Frontend публикуется Nginx и обращается к backend через `/api`.

**Frontend.** Каталог `frontend/` содержит React 18 + TypeScript + Vite. `src/pages` хранит страницы по пользовательским сценариям, `src/components` — переиспользуемые таблицы, графики, модальные окна, состояния загрузки и другие элементы интерфейса, `src/layout` — общий каркас приложения и ролевую навигацию, `src/auth` — состояние авторизации и защиту маршрутов, `src/api` — Axios-клиент, передачу JWT, refresh token, request id и idempotency key, `src/types` — контракты frontend с API. Серверное состояние хранится в TanStack Query. При входе, регистрации и выходе кэш очищается, поэтому персональные данные разных аккаунтов не смешиваются. Графики построены на Recharts. В Docker frontend собирается Node 22 и раздаётся Nginx.

**Backend solution.** Backend находится в `backend/ProbMind.sln` и разделён на проекты `ProbMind.Domain`, `ProbMind.Application`, `ProbMind.Infrastructure`, `ProbMind.Api`, `ProbMind.Worker`, `ProbMind.UnitTests` и `ProbMind.IntegrationTests`. Направление зависимостей сохраняет предметную логику независимой от HTTP и конкретного хранилища: Domain не зависит от инфраструктуры; Application зависит от Domain; Infrastructure реализует интерфейсы Application; Api и Worker являются точками запуска и подключают Application и Infrastructure.

**ProbMind.Domain.** Содержит сущности, enum и value object, а также чистую предметную логику. Здесь находятся расчёт освоения тем, обработка диагностических свидетельств, состояние типичных ошибок, адаптивное ранжирование вопросов, планирование покрытия диагностики, построение учебного плана, коррекционная логика, оценка сложности и различающей способности заданий, надёжность диагностик, когортные показатели, оценка риска студента, IRT и прогноз освоения. Этот слой не содержит доступа к PostgreSQL, Redis или ASP.NET Core.

**ProbMind.Application.** Содержит прикладные сценарии и контракты. Сервисы отвечают за авторизацию, диагностику, преподавательские диагностические шаблоны, практику, модель студента, план повторения, рекомендации, статистику, управление контентом, импорт CSV, рабочее пространство материалов, геймификацию, интервальное повторение, уверенность, группы, индивидуальные задания, экзамены, достижения, учебные циклы, экспорт, уведомления и административные операции. В `Abstractions` описаны интерфейсы репозиториев, Unit of Work, кэша, очереди, времени, хеширования паролей и токенов. В `Validation` находятся валидаторы входных запросов.

**ProbMind.Infrastructure.** Реализует технические зависимости Application. Entity Framework Core и Npgsql работают с PostgreSQL через `ProbMindDbContext`, конфигурации сущностей и репозитории. `UnitOfWork` предоставляет единый набор репозиториев и сохранение изменений. Redis используется как прикладной кэш, хранилище idempotency-ответов и очередь фоновых заданий. Пароли хешируются PBKDF2. JWT создаётся инфраструктурным token service. `Seeding` создаёт обязательные темы, типичные ошибки, тестовые роли, банк заданий и обеспечивает совместимость существующей локальной базы с новыми таблицами и колонками без удаления пользовательских данных.

**ProbMind.Api.** Это ASP.NET Core Web API. Контроллеры сгруппированы по сценариям: авторизация, диагностика, диагностические шаблоны, практика, модель студента, планы, статистика, преподавательские функции, EdTech-механики, геймификация, контент, импорт, материалы, экспорт, исследования и администрирование. Ролевые ограничения проверяются атрибутами авторизации на сервере. В HTTP-конвейере используются security headers, метрики, request logging, единая обработка ошибок, CORS, JWT authentication/authorization и idempotency middleware. Доступны `/api/health`, `/api/ready` и Swagger по `/api/swagger`.

**ProbMind.Worker.** Фоновый Worker читает задания из Redis. Он выполняет пересчёт модели конкретного студента, перестроение рекомендаций и пересчёт групповой аналитики вне пользовательского HTTP-запроса. Сообщения очереди содержат тип задания, идентификатор пользователя при необходимости и correlation id.

**PostgreSQL.** В базе хранятся пользователи и refresh token, темы, задания и версии заданий, варианты ответа, связи дистракторов с типичными ошибками, диагностические сессии и ответы, отчёты, практические сессии и попытки, освоение тем и его история, типичные ошибки студента и диагностические свидетельства, учебные планы и их версии, рекомендации, уведомления, события активности, экспозиции заданий, материалы и заметки, преподавательские диагностики, настройки рейтинга, интервальное повторение, группы и участники групп, индивидуальные задания, экзамены и попытки, учебные циклы и индивидуальный прогресс по ним, персональные достижения и журнал административных действий. Персональные сущности привязаны к `UserId` или `StudentId`, а доступ к адресным диагностическим, экзаменационным и индивидуальным данным дополнительно проверяется на backend.

**Redis.** Redis используется для краткоживущего кэша, очереди фоновых аналитических задач и поддержки идемпотентных изменяющих запросов. Потеря Redis-кэша не заменяет основное состояние PostgreSQL.

**Авторизация и безопасность.** API использует JWT access token и refresh token. Access token имеет ограниченный срок жизни, frontend автоматически обновляет его через refresh endpoint. Роли `Student`, `Teacher` и `Admin` проверяются на backend; frontend-маршруты дублируют ограничения только для интерфейса. Пароли не хранятся в открытом виде. Конфигурация локальных PostgreSQL и JWT находится в `.env.example`, а реальный `.env` исключён из Git через `.gitignore`.

**Диагностика и адаптация.** Адаптивная диагностика выбирает вопросы на сервере. Приоритет учитывает тему, текущее освоение, связанные типичные ошибки, сложность, историю экспозиций и необходимость проверки переноса. Для точных повторов условий используется нормализованный текст вопроса, поэтому одинаковая формулировка с разными идентификаторами не считается новым заданием. Преподавательская диагностика использует фиксированный список выбранных вопросов и может содержать от одной задачи.

**Практика и обучение.** Практика опирается на тему, текущую модель студента и активные ошибки. После ответов обновляются учебные данные, рекомендации и план. Интервальное повторение хранит отдельное расписание по студенту и теме. Уверенность является необязательной метаданной ответа. Достижения хранятся отдельно по студенту; их прогресс пересчитывается из данных текущего пользователя, а полученное достижение сохраняет факт разблокировки.

**Группы и адресные назначения.** Группы представлены отдельными сущностями группы и членства. Диагностики и экзамены могут быть общими, групповыми или персональными. Сервер проверяет аудиторию не только при выводе списка, но и при попытке начать назначение. Индивидуальные задания всегда привязаны к конкретному студенту.

**Экзамены.** Экзамен ссылается на готовую преподавательскую диагностику и хранит аудиторию, лимит времени и попытки студентов. Ответы идут через диагностическую сессию, но во время экзамена промежуточный разбор скрыт. Преподавательский просмотр становится доступен после завершения экзамена всей назначенной аудиторией и показывает ответы каждого участника.

**Учебные циклы.** Цикл «до и после материала» хранит диагностический шаблон до материала, текст материала, диагностический шаблон после материала и аудиторию. Для каждого студента создаётся отдельный прогресс с идентификаторами диагностических сессий, временем открытия материала и изменением результата.

**Схема и начальные данные.** При старте API `DatabaseSeeder` подготавливает локальную базу, добавляет отсутствующие структуры совместимости, системные темы, каталог типичных ошибок, тестовые аккаунты и банк заданий. Обновление проекта не требует удаления существующего Docker volume с PostgreSQL.

**Docker Compose.** `docker-compose.yml` запускает PostgreSQL 16, Redis 7, API, Worker и frontend. Профиль `check` добавляет контейнер для backend-тестов. `Start_ProbMind.command` проверяет Docker, создаёт `.env` из `.env.example`, собирает API, Worker и frontend, запускает контейнеры, ждёт health/ready endpoints и открывает приложение. `Stop_ProbMind.command` останавливает проект. `Check_ProbMind.command` проверяет сборку, сервисы и доступность приложения.

**Тестирование и CI.** `ProbMind.UnitTests` проверяет предметные алгоритмы, аналитику, валидацию и сервисы без полного HTTP-конвейера. `ProbMind.IntegrationTests` запускает API через тестовый host и проверяет авторизацию, ролевую безопасность, диагностические и практические сценарии, экспорт, статистику, контент и технические ограничения. Workflow `.github/workflows/ci.yml` собирает backend на .NET 8 с PostgreSQL и Redis, запускает тесты, затем собирает frontend на Node 22.
